Design and method

How I built the two views

I treated each paragraph or short policy block as one passage. Font size and spacing in the PDF supplied the Part, section, and subsection hierarchy; page numbers were retained, whitespace was normalized, repeated text was removed, and very short fragments were excluded. This produced 957 passages from 984 raw blocks. I encoded the cleaned text with all-MiniLM-L6-v2, using normalized 384-dimensional embeddings. UMAP projected those vectors to two dimensions with 20 neighbors, minimum distance 0.15, cosine distance, and random seed 42. I then ran K-means on the original embeddings, not the UMAP coordinates, using eight clusters and 20 initializations. Topic names came from each cluster’s characteristic TF-IDF terms and representative passages.

On the map, position represents semantic similarity, color represents the labeled topic, and point size represents passage length. Search and the two filters fade irrelevant passages without rearranging the map. Clicking a passage shows its original location and nearest neighbors; clicking a neighbor moves the selection while keeping the surrounding context visible. The matrix uses formal bulletin Parts as rows, topics as columns, and within-Part proportions as color intensity, which keeps the large course-description chapter from overwhelming smaller sections. Clicking a matrix cell highlights the corresponding points, while selecting a point outlines its matrix cell. This coordination makes it possible to move between “where is this written?” and “what does this resemble?” without losing the current selection.
